# 叠放相纸：照片内容

沿用拍立得方向的 P4 叠放（[hyperdr-icon-instant](../hyperdr-icon-instant/README.md)）：后面一张空白相纸转 7°，前面一张转 −3°。上一轮照片里“光点加横线”的含义不清楚，这一轮换成一眼能认出的场景。每个场景都是明暗反差大的题材，最亮的东西就是光源本身，正是 HDR 最擅长的画面。

| 场景 | 画面 | 特点 |
| --- | --- | --- |
| S1 日落 | 半个太阳落在海平线上，水面三道倒影 | 最一眼看懂，也最温暖；倒影把 HDR 的“高光”讲得最直接 |
| S2 山与日 | 灰色天空，两重山的剪影，一个白色太阳 | 就是通用的“照片”符号，最好认，但也最常见 |
| S3 月夜 | 深色夜空，一弯新月，水面倒影 | 最安静、最克制；新月形状在小尺寸下仍然清楚 |
| S4 窗光 | 暗室里一扇亮着的四格窗，地上一片光 | 最少见、最有记忆点；室内逆光是典型的 HDR 场景 |

选定 S2 山与日。定稿时把前面相纸的默认色从 `#F6F4EF` 压到 `#EEEBE4`，让太阳成为全图唯一的纯白；深色外观下把天空和两重山的明度拉开，远山和近山不再糊在一起。

## 文件

- `<场景>/HyperDR.icon`：可以直接用 Icon Composer 打开、也可以直接拖进 Xcode 的图标文件。分组、玻璃、阴影和深色外观的颜色都已经设好，见下文。
- `<场景>/layers/`：给 Icon Composer 用的图层，每个文件是一张 1024 × 1024 的 SVG，只有一个纯色图形，倾斜已经算进坐标。文件名的数字就是从后往前的顺序：`1-back`、`2-card`，然后是照片里的各层。
- `<场景>/preview-light.svg`、`preview-dark.svg`：合成预览，带近似的圆角遮罩和相纸阴影，只用来看效果，不要导入。
- `preview.html`：四个场景在浅色和深色下的 256 / 120 / 60 / 29 px 效果和主屏效果。
- `make_icons.py`：生成以上所有文件。场景定义在照片自己的单位坐标里（0 到 1），颜色写在每一层旁边，格式是（默认外观, 深色外观）。改完运行 `python3 make_icons.py`。

## 导入 Icon Composer

`HyperDR.icon` 已经按下面的方式设好：三组从前到后依次是光源（Liquid Glass 加高光）、照片（不透明、无高光）、两张相纸（阴影）；底色和每层的深色外观颜色都已填好。S2 的 `HyperDR.icon` 已用 `actool` 按 iOS 26 和 macOS 26 编译通过，生成了默认、深色和着色三种外观。默认外观渲染出的 iOS 和 Mac 图标已经看过；深色和着色外观只确认已生成，还要在 Icon Composer 里看一遍。

要从单个图层手动重建时：

1. 新建文档，把所选场景 `layers/` 里的 SVG 拖进侧栏。
2. 分三组：两张相纸一组，打开阴影；照片的底色层一组，保持哑光；光源（太阳、月亮或窗）和倒影一组，打开 Liquid Glass 和高光，让它成为全图最亮的地方。
3. 底色不是图层：在文档的背景填充里设为 `#22211F`，深色外观设为 `#0E0E0D`。
4. 在深色外观下，按 `make_icons.py` 里的第二个颜色逐个覆盖图层的填充色。
5. 单色（着色）外观由系统生成，导入后检查光源是否仍然最突出。

S2 的 `HyperDR.icon` 已复制到 `apps/apple/Shared/AppIcon/`，作为 Mac 和 iOS 两个 App 的图标。在这里改完重新生成后，要把 `s2-mountains/HyperDR.icon` 再复制过去。
