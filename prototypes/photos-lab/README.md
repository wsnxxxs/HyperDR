# HyperDR Photos Lab 操作说明

这是一个**只用来做实验的小 App**，和 HyperDR 的引擎无关。它回答这几个问题：

1. 用系统选择器选照片，拿到的文件里**增益图**还在吗？RAW / ProRAW 拿到的是原文件吗？
2. 普通 App（不是照片扩展）能不能**原地编辑**图库里的照片，并且写回**带增益图的 HEIC**？
3. 写进去的配方（adjustmentData）能不能读回来？“复原”之后图库是否回到原样？
4. “存为新照片”导入带增益图的 HEIC / JPEG，增益图保留吗？
5. 图库只给了“受限访问”时，还能原地编辑吗？

它会改你图库里的照片，所以**请只用测试照片，不要用重要照片**（见下面“选什么照片测”）。每一步都由你手动点按钮，不点就不会碰图库。

---

## 一、在 Mac 上运行

1. 用 Xcode 打开 `prototypes/photos-lab/PhotosLab.xcodeproj`。
2. 左上角方案选 **PhotosLab**，运行目标选 **My Mac**。
3. 第一次如果提示签名问题：点左侧项目 → 目标 PhotosLab → Signing & Capabilities，Mac 这一栏保持 **Sign to Run Locally**（已默认设好，不需要开发者账号）。
4. 点运行（▶）。窗口里能看到“选照片”“测试步骤”“日志文件”“结果”几个区块。
5. 系统会在你第一次点“选照片”时弹出照片选择窗口（这个窗口由系统提供，不需要授权）。真正需要授权的是第 1 步里访问图库的时候，见第三部分。

## 二、在 iPhone / iPad 上运行（免费 Apple ID 就够）

不需要付费开发者账号。iOS 上访问照片图库只靠 Info.plist 里的权限说明，这个 App 在 iOS 上没有申请任何 entitlement 或需要付费账号的 capability。

1. 在 Xcode 里登录你的 Apple ID：Xcode → Settings → Accounts → 左下角“+”→ Apple ID。登录后会出现一个 **Personal Team**（个人团队）。
2. 用线连接 iPhone 或 iPad，解锁并点“信任此电脑”。
3. 在设备上打开开发者模式：设置 → 隐私与安全性 → 最下面的“开发者模式”→ 打开，按提示重启，重启后再确认一次。（第一次连上 Xcode 之前这一项可能不显示，连接并在 Xcode 里选中设备后就会出现。）
4. 在 Xcode 里选工程 → 目标 PhotosLab → Signing & Capabilities：**Team 选你的 Personal Team**（我没有填 Team）。保持“Automatically manage signing”。
5. 免费账号要求 Bundle Identifier 全局唯一。如果提示“Failed to register bundle identifier”，把 `com.hyperdr.PhotosLab` 改成 `com.你的名字.PhotosLab`。
6. 运行目标选你的 iPhone 17 Pro 或 iPad Pro，点运行（▶）。
7. 第一次安装后设备上会提示“不受信任的开发者”。到 设置 → 通用 → VPN 与设备管理 → 点你的 Apple ID → “信任”，再打开 App。
8. **免费账号装的 App 7 天后过期**，到期后图标点开会闪退。重新在 Xcode 里点运行（▶）重装即可，App 里的日志文件会保留。另外免费账号同一台设备上最多同时装 3 个这类 App。
9. iPhone、iPad 各装一次，各测一遍（结果可能不同）。**不要用模拟器做这个测试**：模拟器的图库不是你的图库，而且模拟器里的 ImageIO 不能生成增益图。

## 三、选什么照片测

先把测试照片放进“照片”App（Mac 上：打开“照片”→ 文件 → 导入；开了 iCloud 照片的话会自动同步到手机/iPad）。**导入的是副本，测完可以删。**

建议至少测这几张（在你桌面的“测试照片”文件夹里）：

| 照片 | 测什么 |
|---|---|
| `IMG_3891.HEIC`（iPhone，同时带 ISO 和 Apple 增益图） | **主测试照片**，最先测这张 |
| `IMG_3250.heic`（iPhone 12 Pro Max，旧式 Apple 增益图） | 旧式增益图能不能保住 |
| 小米 Ultra HDR JPEG（`IMG_20261007…edit.jpg`） | JPEG 增益图 |
| `DSC01468.ARW`（A7R V 的 RAW） | 选择器拿到的是不是 RAW 原文件 |
| `DSC01422.HIF`（索尼 10 位 HLG） | 10 位 HEIF |
| `IMG_8681.JPG`（普通 JPEG，无增益图） | 对照组：没有增益图时的表现 |

如果你有真正的 iPhone ProRAW（DNG）照片，也建议单独拍一张测试。

## 四、测试步骤

每次测一张照片，从上往下点。下面的“会弹什么”是我预期的，实际以屏幕为准——**弹的框本身也是实验结果，请照实记下来**。

### 0. 选照片
- 点“选照片…”，在系统选择器里点一张照片，确认。
- 界面会显示“已选：…”和一串标识。如果显示“选择器没有给出图库标识”，说明这张照片后面的原地编辑没法做，请记下来。

### 1. 检查原文件
- 点“**1 检查原文件**”。
- **会弹**：“照片”访问授权框（只有第一次）。有三个选项：
  - “允许访问所有照片”→ 完全访问；
  - “选择照片…”→ 受限访问（测第六部分时用）；
  - “不允许”→ 后面都做不了。
  测主流程请先选“允许访问所有照片”。
- 它会做两件事：检查选择器给你的文件（有没有 ISO 增益图、Apple 增益图、是不是 RAW、位深多少），再从图库读出这张照片的原始资源做对比。
- 看结果区：
  - ✅ “选择器文件与图库原始资源……字节完全一致”= 选择器给的就是原文件。
  - ❌ “增益图丢失”或“RAW 变成了别的格式”= 选择器转码了，请交回日志。

### 2. 原地编辑写回
- 先在“写回设置”里选**输出格式**（默认“HEIC + ISO 增益图”），曝光默认 +0.3 EV。adjustmentData 大小默认约 1 KB。
- 点“**2 原地编辑写回**”。
- **会弹**：系统的“修改这张照片？”确认框，点“修改”。如果弹框被取消或报错，结果区会显示错误码。
- 这一步做的事：向系统要编辑输入 → 提亮 0.3 EV → 按你选的格式写出渲染文件 → 把配方存进 adjustmentData → 提交。
- 同一步会把系统支持的渲染格式列表写进日志（`supportedRenderedContentTypes`），这是我们最想要的信息之一。

### 3. 读回检查
- 点“**3 读回检查**”。
- 看结果区：
  - adjustmentData 能不能读回、内容和写入的是否一致；
  - 读回的当前版本里增益图是否还在、位深和类型有没有变；
  - 平均亮度是不是大约变亮了 ×1.23（+0.3 EV 的理论值；已经很亮的高光会小一些）；
  - 图库给出的全部资源列表。
- **请你再手动做一件事**：打开系统“照片”App，找到这张照片，看它是不是亮了一点，右上角有没有 HDR 标记，点“编辑”看有没有“还原”。把你看到的告诉我。

### 4. 复原
- 点“**4 复原**”。
- **可能会弹**：系统确认框。
- 看结果区：复原后 `hasAdjustments` 应为 false，adjustmentData 应被清除，photo 资源应与第 1 步字节一致。
- 然后再打开“照片”App，确认照片回到原样。**这一步做完图库就恢复原状了。**

### 5. 存为新照片
- 先做过第 1 步（需要素材）。点“**5 存为新照片**”。
- **会弹**：系统的“添加”确认框，会弹两次（一张是编辑后的版本，一张是原文件对照）。
- 结果区会逐个说明：导入后增益图保留了吗？字节一致吗？
- 这一步会在你的图库里新增**两张**照片，文件名以 `PhotosLab-` 开头。

### 6. 删除新照片
- 点“**6 删除新照片**”。系统会弹删除确认框，点“删除”。
- 删掉的照片会进“最近删除”，**请到“照片”App → 最近删除里手动清空**，否则会占着 30 天。
- 界面上如果还有橙色的“图库里还有 N 张本测试创建的新照片”提示，说明还没删。

### 依次运行 1–4
想省事可以点“依次运行 1–4”，会连着做检查、编辑、读回、复原，中间会弹两次确认框。某一步失败就停。第 5、6 步单独点。

### 换格式再测
同一张照片可以换“输出格式”再从第 2 步测一遍（记得每次测完都点第 4 步复原）。四种格式的意思：

- **HEIC + ISO 增益图（ImageIO）**：我们最想要的路径。
- **JPEG + ISO 增益图**：如果系统不接受 HEIC，试这个。
- **HEIC 10 位 PQ，无增益图**：看系统接不接受 10 位。
- **HEIC 8 位底图 + 搬运原图增益图**：备用路径，自己写底图、把原图的增益图原样带过去。万一第一种在设备上写不出来，用它。

### adjustmentData 大小上限
把“adjustmentData 大小”依次改成 100 KB、1 MB、10 MB，各测一遍第 2、3 步，看哪个大小开始写不进或读不回。

## 五、受限访问（Limited）测试

1. 在第 1 步弹授权框时选“选择照片…”并**只勾选**要测的那张照片（或者先去“设置 → 隐私与安全性 → 照片 → Photos Lab”改成“受限访问”）。
2. 回到 App，界面上“图库权限”应显示 `limited`。重新选照片，做第 1、2、3、4 步，看每一步的结果。
3. 再测另一种情况：用受限访问，但**不勾选**你在选择器里挑的那张照片。预期的日志是“按标识找不到这张照片”——请照实交回。
4. iPhone/iPad 上受限时，界面上会多一个“管理受限照片…”按钮，可以改勾选的照片。Mac 上去“系统设置 → 隐私与安全性 → 照片”里改。

## 六、日志在哪里

界面“日志文件”区块里直接显示了完整路径，并有“分享/导出日志”按钮（AirDrop、邮件、存到文件都行）。Mac 上还有“在访达中显示”。

- Mac：`~/Library/Containers/com.hyperdr.PhotosLab/Data/Documents/photos-lab-log-<时间>.json`
- iPhone / iPad：打开“文件”App → 我的 iPhone（或 iPad）→ **Photos Lab** 文件夹。

每次启动 App 生成一份新日志；每点一步就自动保存，中途闪退也有记录。**测完把所有 `photos-lab-log-*.json` 交给我**，并附上：
- 设备型号和系统版本（日志里自动带了）；
- 你在“照片”App 里亲眼看到的情况（第 3、4 步里让你看的那些）；
- 每次弹出的系统框是什么。

---

## 七、测完怎么清理

1. 每张测过的照片：确认第 4 步“复原”已经做过，且“照片”App 里显示是原图。
2. 点“6 删除新照片”，再到“照片”App → 最近删除里清空。
3. 点“清除临时文件”（清掉 App 临时目录里的中间文件；日志不会被清掉）。
4. 如果你把测试照片导入了图库，在“照片”App 里把它们删掉，也清空“最近删除”。
5. 可以把 Photos Lab 从设备上删除；想撤销授权：设置 → 隐私与安全性 → 照片 → Photos Lab → 不允许。

## 八、已知风险与注意

- **iCloud 照片**：如果开了 iCloud 照片，编辑和复原都会同步到你的其他设备。一定用测试副本。
- **原图在 iCloud 里没下载**：App 允许从 iCloud 下载，大文件会慢；界面上看不到进度，请耐心等待。日志里有耗时。
- **61MP 以上的大图**：在 iPhone/iPad 上渲染可能内存吃紧。第一次测请先用手机拍的照片（`IMG_3891.HEIC`、`IMG_3250.heic`），最后再试索尼的大图。
- **模拟器不能用来做实验**：见上面第二部分。
- **输入照片没有增益图时**：ImageIO 不会生成增益图，日志会写明这一点，这不是图库的问题。（对照组 `IMG_8681.JPG` 会看到这个。）
- ImageIO 写出的 10 位 PQ HEIC 回读时 headroom 显示 1.0，而 Core Image 写出的显示正常值，这是已知的 ImageIO 与 Core Image 差异，不是图库造成的。
- 我没有测过“仅添加”（add-only）权限下能不能创建和编辑，因为授权框只在第一次问；要测需要先在“设置”里把权限重置，然后选择仅添加。如果想测，告诉我，我再加。

## 开发者备注

- 工程是单个多平台目标（iOS 26 / iPadOS 26 / macOS 26），不依赖任何第三方库。
- `Sources/Core` 里是不碰图库的纯 ImageIO / Core Image 代码（检查文件、写增益图、日志），`Tests` 里有对它们的单元测试，不会碰图库：

  ```sh
  DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  xcodebuild test -project PhotosLab.xcodeproj -scheme PhotosLab -destination 'platform=macOS'
  ```
- 在模拟器上跑同样的测试时，需要增益图编码器的用例会自动跳过。
- `Sources/App` 里是界面和 PhotoKit 调用，只在用户点按钮时才执行。
